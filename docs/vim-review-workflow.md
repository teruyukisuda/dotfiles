# vim + terminal で Claude Code の変更をレビューする

2026-10-14 に整備した構成のまとめ。IDE を使わず、vim / tmux / bash だけで
Claude Code に書かせたコードをリポジトリ単位で確認するための設定と手順を書く。

対象ファイルはすべて `~/dotfiles` にある。

| ファイル | 役割 |
|---|---|
| `.vimrc` | vim 本体の設定。末尾の「Git レビュー」節にレビュー用キーをまとめてある |
| `rc/dein.toml` | dein で管理するプラグイン一覧 |
| `.bashrc` | 末尾に fzf の初期化と `changed` / `review` / `cw` 関数 |
| `~/.gitconfig` | delta を git の pager にする設定（dotfiles 管理外） |

同じディレクトリの `vim-review-tutorial.md` は、練習用のリポジトリを作って
この文書の操作を最初から最後まで一度通すチュートリアル。

---

## 0. 最短の流れ

```
cw ~/project/iso/<repo>     # tmux に左シェル / 右 claude のウィンドウを作り、右で実装させる
changed                     # 変更が入ったリポジトリを一覧する
review                      # 1 つ選ぶと vim が開く。タブ 1 がステータス、タブ 2 以降が差分
```

vim の中では次を繰り返す。

- `gt` で次のファイル、`]h` で次のハンクへ進む
- 採用するハンクは `,hs`、戻すハンクは `,hu`、直すなら右側のウィンドウで編集して保存
- 新規ファイルはタブ 1（`,gs`）の Untracked に出る。`o` で分割して開いて読み、`:q` で戻って `-` でステージ
- タブ 1 で未ステージが残っていなければ `cc` でコミット

`:qa` で抜けて `review` を再実行し、`changed` が空になるまで繰り返す。
用語や仕組みがわからなければ 2 章、各操作の意味は 3 章、手順の詳細は 4 章にある。
練習用のリポジトリで一通り試すチュートリアルは `vim-review-tutorial.md`。

## 2. 前提知識と段階的な覚え方

vim のプラグインや git の用語に慣れていない人向けに、3 章以降を読むのに必要な知識と、
覚える順番を書く。知っていれば飛ばしてよい。

### 2-1. vim 側の用語

**プラグイン**

vim 本体に無い機能を足すための、vimscript ファイルのまとまり。GitHub のリポジトリ 1 つが 1 プラグイン。
この環境では `~/.cache/dein/repos/github.com/<作者>/<名前>/` に clone されていて、
その中の `plugin/`（起動時に読まれる）、`autoload/`（必要になったとき読まれる）、`doc/`（ヘルプ）などを
vim が `runtimepath` という設定を通して読む。

例えば fugitive は `:Git` というコマンドとステータス画面の中のキー（`-` `cc` など）を足し、
gitgutter は左端の記号列と `,hs` のような操作を足す。どのプラグインが何を足しているかは
1-2 の表と、`rc/dein.toml` のコメントに書いてある。

**dein**

プラグインを入れたり更新したりする役のプラグイン（プラグインマネージャ）。`rc/dein.toml` に

```
[[plugins]]
repo = 'tpope/vim-fugitive'
```

と書くと、`.vimrc` の dein の節がこれを読み、`dein#check_install()` が未インストールのものを見つけて
`dein#install()` で clone し、`runtimepath` に加える。つまり

- 足す: toml に 3 行書いて vim を起動し直す
- 外す: toml から消して vim を起動し直す。clone したディレクトリは残るので、
  `:echo dein#check_clean()` で出てくるパスを不要なら手で消す
- 更新: `:call dein#update()`

**キーの読み方と Leader**

`.vimrc` の `nnoremap <silent> <Leader>gs :Git<CR>` は「ノーマルモードで `,` `g` `s` と順に押したら
`:Git` を実行する」という意味。Leader はこの環境では `,`。同時押しではなく順押し。
`nmap ]h <Plug>(GitGutterNextHunk)` の `<Plug>(...)` は、プラグインが用意している名前付きの操作で、
それにキーを割り当てている。

`s` は `nnoremap s <Nop>` で単体の意味を消し、`sj` `sv` `sq` のようなウィンドウ操作の頭文字にしてある。
押したキーが何に割り当てられているかは `:nmap ,gs` や `:verbose nmap ]h` で確認できる
（`verbose` を付けると、どのファイルの何行目で定義されたかも出る）。

**バッファ・ウィンドウ・タブ**

バッファは読み込んだファイルの中身、ウィンドウはそれを映す枠、タブはウィンドウの並べ方のひとまとまり。
`,gD` で開く「差分タブ」は、1 タブに左右 2 ウィンドウという構成。

| 対象 | 移動 | 閉じる |
|---|---|---|
| タブ | `gt` `gT` | `:tabclose` |
| ウィンドウ | `sj` `sk` `sh` `sl` | `sq`（`:q`） |
| バッファ | `sn` `sp`、一覧は `sb` | `sQ`（`:bd`） |

差分タブとウィンドウをまとめて片付けるのが `,gq`、vim ごと終わるのが `:qa`。

**diff モード**

2 つのウィンドウの内容を突き合わせて違いに色を付ける vim の機能。スクロールが連動し、
`]c` `[c` で違いの間を移動し、`do` `dp` で片方の内容をもう片方に写す。
行を揃えるために `------` の詰め物の行が出る。詳細は `:help diff-mode`。

**fugitive:// バッファ**

`:Git` のステータス画面や差分タブの左側は、ファイルではなく fugitive が git の情報から作った仮想バッファで、
名前が `fugitive://` で始まる。この環境では一覧（`sb` `:ls`）に出ないよう設定してある。

**プレビューウィンドウと quickfix**

`,hp` の出力は「プレビューウィンドウ」という専用の小窓に出る。閉じるのは `:pclose`（`Ctrl-W z`）。
`,hq` や、`:Rg` で複数選んだ結果は quickfix（場所の一覧）に入り、`]q` `[q` で順に回れる。

**ヘルプ**

`:help fugitive-maps` `:help gitgutter` `:help fzf-vim` `:help git-messenger` `:help dein` で
各プラグインの説明が読める。fugitive の画面では `g?` でその画面のキー一覧が出る。

### 2-2. git 側の用語

- **作業ツリー**: 手元のファイルそのもの。Claude Code はここを書き換える。
- **index**（ステージ、staging area とも言う）: 次のコミットに入れる内容の置き場。
  `git add`、fugitive の `-`、gitgutter の `,hs` はここに書く。
- **HEAD**: 最後のコミット。
- **ハンク**: 差分のひとかたまり。連続した変更行と前後の文脈行で 1 つ。gitgutter の記号のひとつながりが 1 ハンク。

比較の組み合わせは 3 つあり、レビューではこれを使い分ける。

| 比較 | git のコマンド | vim での見方 |
|---|---|---|
| index と作業ツリー（まだステージしていない変更） | `git diff` | `,gD`、gitgutter の記号 |
| HEAD と index（ステージ済みの変更） | `git diff --cached` | ステータス画面の Staged 欄で `=` |
| HEAD と作業ツリー（両方まとめて） | `git diff HEAD` | `,gH`、`review` |

3-1 の「ステージ済み = レビュー済み」という考え方はこの区別に乗っている。
index に入れた変更は `,gD` と gitgutter の記号から消えるので、残っている記号が未レビュー分になる。

### 2-3. 段階的に覚える

一度に全部覚える必要はない。次の順で、各段階が手に馴染んでから次へ進む。

**Step 1. ステータス画面だけで回す**

覚えるキー: `,gs` `=` `-` `cc` `gq` `g?`

ファイル単位で「全部採用」か「全部却下」ができる。`,gs` でステータス画面を出し、
`=` でカーソル行のファイルの差分をその場で開いて読み、`-` でステージ、`cc` でコミット。
却下するファイルは `X`（作業ツリーの変更が消えるので、迷ったら押さない）。
これだけで、小さな変更のレビューは成立する。

**Step 2. 左右差分で読む**

覚えるキー: `,gD` `gt` `gT` `]c` `[c` `,gq`

変更のあるファイルがタブに並び、左が比較元、右が今のファイルになる。
行単位で何が変わったかを目で追える。直したい箇所は右のウィンドウで編集して `:w`。
ここまでで「手直しして採用」ができる。`,gH` と `review` は比較元が HEAD になるだけで操作は同じ。

**Step 3. ハンク単位で仕分ける**

覚えるキー: `]h` `[h` `,hp` `,hs` `,hu`、あわせて `:w` と `:pclose`

1 ファイルの中で採用と却下を混ぜられる。`,hs` は git に直接書くので保存不要、
`,hu` はバッファを書き換えるので `:w` が要る、という違いだけ押さえる。
ビジュアル選択してから `,hs` を押すと行単位で選べる。

**Step 4. 調べる**

覚えるキー: `,gm` `,gb` `,gl` `,gf` `,r` `,R` `,uf` `,ub`

「なぜこの行がこうなっているか」「同じ書き方が他にあるか」を vim の中で調べられる。
`,gm` でカーソル行を書いたコミットがポップアップで出て、`,r` でリポジトリ全体を文字列検索できる。

**Step 5. 複数リポジトリ**

覚えるコマンド: `changed` `review` `cw`

ターミナル側のヘルパーで、変更のあるリポジトリを一覧し、選んで vim を開き、
tmux に Claude Code 用の作業ウィンドウを作る。4 章で扱う。

Step 1 から 3 と Step 5 を実際に通す練習が `vim-review-tutorial.md`。

## 3. レビューの手法と操作

### 3-1. 考え方

Claude Code が書いた変更は、コミットする前に次の 3 つに仕分ける。

1. そのまま採用する → ステージする
2. 手直しして採用する → vim で直してからステージする
3. 採用しない → ハンク単位で取り消す

ステージ済みかどうかが「レビュー済みかどうか」の印になる。
未ステージの変更がなくなったらそのリポジトリのレビューは終わり。

### 3-2. vim のキー

Leader は `,`。

**全体を見る（fugitive）**

| キー | 動作 |
|---|---|
| `,gs` | `:Git`。ステータス画面を開く |
| `,gD` | `:Git difftool -y`。未ステージの変更があるファイルを全部タブで開き、index と左右比較する |
| `,gH` | `:Git difftool -y HEAD`。ステージ済みも含めて HEAD との差分を全部タブで開く |
| `,gd` | `:Gvdiffsplit`。今のファイルだけ左右比較 |
| `,gq` | レビューで開いたタブとウィンドウを閉じて 1 つに戻す |
| `,gl` | 直近 50 件の `git log --oneline` |
| `,gb` | `:Git blame` |

ステータス画面（`,gs`）の中で使うキーは fugitive のもの。

| キー | 動作 |
|---|---|
| `=` | カーソル行のファイルの差分をその場で展開 / 折りたたみ |
| `dv` | カーソル行のファイルを左右差分で開く |
| `-` | ステージ / アンステージを切り替える |
| `X` | その変更を捨てる（ワークツリーの変更を破棄するので注意） |
| `cc` | コミットメッセージを書いてコミット |
| `)` `(` | 次 / 前のファイル・ハンクへ |
| `o` | カーソル行のファイルを横分割で開く。Untracked の新規ファイルを読むときはこれを使い、読み終えたら `:q` で戻る |
| `Enter` | カーソル行のファイルをステータス画面のウィンドウに開く（ステータス画面が置き換わる）。戻すには `:Gedit :` |
| `gq` | ステータス画面を閉じる |

**新規ファイルについて。** `,gD` `,gH` `review` が開く差分タブは git が追跡しているファイルだけで、
新規ファイルは出てこない。新規ファイルはステータス画面の Untracked 欄に出るので、
`o` で開いて全体を読み、`:q` で戻って、採用するなら `-` でステージする。

差分タブは左が比較元（`,gD` と `,gd` なら index、`,gH` と `review` なら HEAD）、右が作業ツリーのファイル。
コードを直すのは右のウィンドウで行う。左が index のときは左も編集でき、左で `:w` すると
その内容が index に書き込まれる（= ステージ）。左が HEAD のときは編集しても保存できない。
カーソルの初期位置は `,gD` `,gH` `review` では右、`,gd` では左になる。
Vim 標準の diff モードのキーが使える。

| キー | 動作 |
|---|---|
| `]c` `[c` | 次 / 前の差分へ |
| `gt` `gT` | 次 / 前のタブ（= 次のファイル）へ |
| `do` | 右のウィンドウで押すと、左（比較元）の内容を取り込む。つまりその差分を元に戻す |
| `dp` | 右のウィンドウで押すと、右の内容を左に送る。左が index のとき、続けて左で `:w` するとその差分がステージされる |

`do` と `dp` は差分 1 つ分に効く。ハンク単位の操作は下の gitgutter のキーでも同じことができる。

**ハンク単位で扱う（gitgutter）**

| キー | 動作 |
|---|---|
| `]h` `[h` | 次 / 前のハンクへ。左右差分のタブの中では Vim の `]c` `[c` と同じ動きになる（gitgutter が diff モードではそう切り替える） |
| `,hp` | ハンクの差分を下のプレビューウィンドウに出す。開いたままだと `]h` `[h` に追従する。閉じるのは `:pclose` |
| `,hs` | ハンクをステージ。git に直接書くので `:w` は不要。ビジュアル選択してから押すと選んだ行だけステージできる |
| `,hu` | ハンクを取り消して index の内容に戻す。バッファを書き換えるだけなので、続けて `:w` で保存する |
| `,hq` | 全ハンクを quickfix に流す。`]q` `[q` で巡回 |
| `,hf` | 変更のない行を折りたたんでハンクだけ表示 |
| `ih` `ah` | ハンクをテキストオブジェクトとして扱う（`dih` でハンク削除、`yah` でヤンクなど） |

ステージしたハンクは記号が消える。残っている記号が未レビュー分。

**探す（fzf.vim）**

| キー | 動作 |
|---|---|
| `,gf` | `:GFiles?`。変更のあるファイルを選んで開く |
| `,gc` | `:BCommits`。今のファイルのコミット履歴 |
| `,gC` | `:Commits`。リポジトリのコミット履歴 |
| `,gm` | カーソル行の blame をポップアップ表示 |
| `,uf` | `:Files` |
| `,ub` | `:Buffers`（`sb` も同じ） |
| `,um` | `:History`。最近開いたファイル |
| `,ua` | `:GFiles`。git 管理下のファイル |
| `,r` | `:Rg`。入力した文字列で全文検索 |
| `,R` | カーソル下の単語で `:Rg` |

fzf の画面では `Enter` で現在のウィンドウ、`Ctrl-T` でタブ、`Ctrl-X` で横分割、
`Ctrl-V` で縦分割に開く。`Ctrl-/` でプレビューの表示切り替え。

### 3-3. ターミナルのコマンド

delta を pager にしたので、`git diff` `git show` `git log -p` の出力が
左右並び・行番号付き・シンタックス色付きになる。

| 操作 | 内容 |
|---|---|
| `n` / `N` | pager 内で次 / 前のファイルへ |
| `git -c delta.side-by-side=false diff` | 画面が狭いときに上下並びで見る |
| `git add -p` | 対話的な部分ステージ。delta が色付けする |
| `tig status` / `tig` | 既存の `.tigrc` のまま。履歴をたどるときに使う |

### 3-4. プラグイン別の使い方

3-2 に出てこない、各プラグインの画面の中でのキーをまとめる。
いずれも対象の画面で `g?` を押すとプラグイン側のヘルプが出る（git-messenger は `?`）。

**fugitive の blame 画面（`,gb`）**

右に作業ファイル、左に blame が出て、スクロールが連動する。

| キー | 動作 |
|---|---|
| `Enter` | blame を閉じ、その行を追加したコミットの差分へ移動する |
| `o` / `O` | 同じものを横分割 / 新しいタブで開く。blame は閉じない |
| `-` | カーソル行のコミット時点でもう一度 blame する（履歴をさかのぼる） |
| `A` `C` `D` | 列幅を author / commit / date まで縮める |
| `gq` | blame を閉じて作業ファイルに戻る |

**fugitive のログ画面（`,gl`）**

`git log --oneline -50` の出力が横分割の一時バッファで開く。

| キー | 動作 |
|---|---|
| `Enter` | カーソル行のコミットを開く（`git show` 相当の内容。変更ファイル名の上でさらに `Enter` を押すとそのファイルの差分へ） |
| `o` | 同じものを横分割で開く |
| `gq` | ログ画面を閉じる |

コミットを開いた画面でも `Enter` `o` `gq` は同じ意味で使える。

**fugitive のコミット画面で使う操作（`,gs` の Unpushed / Unpulled 欄、ログ画面、`:Commits` から開いた画面）**

| キー | 動作 |
|---|---|
| `coo` | カーソル行のコミットを checkout |
| `crc` | カーソル行のコミットを revert してコミット |
| `crn` | revert を index と作業ツリーに反映するだけでコミットしない |

**git-messenger（`,gm`）**

カーソル行を最後に変更したコミットの情報をポップアップで出す。ポップアップが出ている間は次のキーが効く。

| キー | 動作 |
|---|---|
| `q` | 閉じる |
| `o` / `O` | その行のひとつ古い / 新しいコミットへ |
| `d` / `D` | このファイルの差分 / コミット全体の差分を表示切替 |
| `r` / `R` | 同じく単語単位の差分で表示切替 |
| `?` | キー一覧 |

ポップアップの外でカーソルを動かすと閉じる。

**fzf.vim の画面の中**

fzf.vim のコマンドはどれも同じ画面で動く。3-2 に書いた `Enter` `Ctrl-T` `Ctrl-X` `Ctrl-V` `Ctrl-/` に加えて次が使える。

| キー | 動作 |
|---|---|
| `Tab` / `Shift-Tab` | 複数選択の切替。`:Rg` で複数選んで `Enter` すると quickfix に入り、`]q` `[q` で巡回できる |
| `Alt-A` / `Alt-D` | `:Rg` で全選択 / 全解除 |
| `Ctrl-O` | 選択中の項目を元のウィンドウで開き、fzf は開いたままにする。候補を順に見比べるときに使う |
| `Alt-Enter` | 開く代わりに、選択項目の文字列（ファイルパス、`:Rg` なら一致した行、`:Commits` ならハッシュ）を現在のバッファに挿入する |

`:Commits` `:BCommits`（`,gC` `,gc`）では `Enter` でそのコミットの内容が開く。`Ctrl-Y` でハッシュをレジスタにコピーし、`Ctrl-S` で並び順を切り替える。

`:GFiles?`（`,gf`）のプレビューには delta が使われ、ファイルごとの差分が右側に出る。

**gitgutter の補足**

- `,hs` でハンクの一部だけをステージするには、ビジュアルモードで行を選んでから `,hs` を押す。
  追加行だけのハンクであればこれで足りる。追加と削除が混ざったハンクの一部を取りたいときは、
  `,hp` でプレビューを出し、`Ctrl-W P` でプレビューウィンドウへ移り、ステージしたくない行を消してから
  そのウィンドウで `:w` するか `,hs` を押す。
- `:GitGutterDiffOrig` で、index との差分を Vim の左右 diff で開ける。`,gd` と似ているが、
  こちらは gitgutter が持っている差分をそのまま出す。

## 4. Claude Code と組み合わせた運用

### 4-1. シェル関数

`.bashrc` 末尾に定義。探索先の既定値は `~/project/iso` 直下と `~/project/iso/worktrees` 直下。
環境変数 `REVIEW_ROOT` で変えられる。引数でも指定できる。

| 関数 | 動作 |
|---|---|
| `changed [root]` | 未コミットの変更があるリポジトリを、変更ファイル数の多い順に表示 |
| `review [root]` | 変更のあるリポジトリを fzf で選び、そこへ `cd` して vim を開く。プレビューに `git status --short` と `git diff --stat HEAD` が出る |
| `cw [dir]` | tmux に新しいウィンドウを作り、左ペインをシェル、右ペインで `claude` を起動する。ウィンドウ名はディレクトリ名 |

`review` で開く vim は次の状態になっている。

- タブ 1: `:Git` のステータス画面（untracked ファイルもここに出る）
- タブ 2 以降: HEAD と差分のあるファイルが 1 ファイル 1 タブで左右比較

### 4-2. 1 リポジトリの流れ

1. `cw ~/project/iso/<repo>` で作業ウィンドウを作る。右ペインの Claude Code に実装させる。
2. 実装が終わったら Claude に `git diff --stat` と `git status --short` を出させて変更範囲を把握する。
3. 差分タブを開く。どちらか一方でよい。
   - 左ペインで `review` を実行してこのリポジトリを選ぶ（HEAD との差分タブ + ステータス画面）
   - または左ペインで `vim` を起動し `,gD` を叩く（index との差分タブだけ）
4. タブを `gt` で送りながら差分を読む。直したい箇所は右のウィンドウで編集して保存する。
5. 採用するハンクは `,hs`、戻すハンクは `,hu`。
6. 新規ファイルはステータス画面（`review` ならタブ 1、`,gD` なら `,gs`）の Untracked 欄にある。
   `o` で分割して開いて読み、`:q` で戻って、採用するなら `-` でステージする。
7. ステータス画面で未ステージが残っていないことを確認し、`cc` でコミットする。
   Claude にコミットさせる場合は、ステージ済みの内容だけをコミットするよう伝える。

### 4-3. 複数リポジトリの流れ

1. Claude Code に複数リポジトリへ変更を入れさせる。
2. ターミナルで `changed` を実行し、どのリポジトリに変更が入ったかを確認する。
3. `review` で 1 つ選ぶと、差分タブとステータス画面が開いた状態で vim が起動する。
   4-2 の手順 4 から 7 を行う（手順 3 は `review` が済ませている）。
4. `:qa` で vim を抜け、`review` を再度実行して次のリポジトリへ。
5. `changed` の出力が空になったら全リポジトリのレビューが終わり。
   コミット済みでも untracked ファイルが残っていると `changed` に出続けるので、
   不要な生成物は削除するか `.gitignore` に入れる。

### 4-4. 注意点

- `X`（fugitive）と `,hu`（gitgutter）はワークツリーの変更を破棄する。元に戻せないので、
  迷う場合は `,hp` でプレビューしてから判断する。
- `,gD` は index との比較なので、ステージ済みのハンクは表示されない。
  ステージ後にもう一度全体を見たいときは `,gH` を使う。
- gitgutter の記号は、操作を止めてから `updatetime`（0.1 秒）後に更新される。
  古く見える場合は `:GitGutter` で更新できる。
- `review` と `changed` は `.git` が存在するディレクトリだけを対象にする。
  worktree（`.git` がファイル）も対象に入る。
- fugitive のステータス画面では、fugitive 本来の `s`（ステージ）を外してある。`s` 始まりの
  ウィンドウ操作キー（`sj` `sv` `sq` など）と衝突するため。ステージは `-` で行う。
- fugitive:// の比較元バッファとステータス画面はバッファ一覧に出ない。`:bn` `:bp` `sb`（`:Buffers`）には
  作業ツリーのファイルだけが並ぶ。
- 差分タブの中でファイルを移るときは `gt` `gT` を使う。`sn` `sp` はバッファ移動なので、差分ウィンドウで
  押すと片側だけが別のファイルに置き換わって左右の対応が崩れる。崩れたら `,gq` で閉じて `,gD` を開き直す。
- HEAD と比較するタブ（`,gH` `review`）では `]h` `[h` が diff モードの `]c` `[c` として動くので、
  ステージ済みで右側に記号の付いていない行にも止まる。そこで `,hs` `,hu` `,hp` を押しても何も起きない。
  gitgutter の操作対象は右側に記号が付いている行だけ。
- `,gH` `review` の左側（HEAD 時点のファイル）にも gitgutter の記号が出る。これは HEAD とその 1 つ前の
  コミットとの差分で、今回のレビューとは無関係。コミットが 1 つしかないリポジトリでは
  `g:gitgutter_diff_base (...^) is invalid` という警告も出る。どちらも無視してよい。

## 5. 設定を反映する手順

```
# dotfiles の symlink を張り直す

# vim のプラグインを入れる

vim

source ~/dotfiles/.bashrc
```

brew で入れたものは `fzf` と `git-delta`。`rg` と `tig` は以前から入っている。
