# vim + terminal で git の変更をレビューする

IDE を使わず、vim / tmux / bash だけで変更を読むための設定と手順をまとめる。
対象は 2 種類ある。

- **未コミットの変更**: Claude Code に書かせて、まだコミットしていないもの
- **コミット済みの変更**: Claude Code がコミットまで済ませたもの、日常のコミット、特定のコミットとコミットの間

前者は fugitive のステータス画面で、後者は `autoload/review.vim` に実装した `:Review` で見る。

対象ファイルはすべて `~/dotfiles` にある。

| ファイル | 役割 |
|---|---|
| `.vimrc` | vim 本体の設定。「Git レビュー」節にレビュー用のキーがある |
| `plugin/review.vim` / `autoload/review.vim` | `:Review` コマンドの定義と実装、`<Space>q` で呼ぶ関数 |
| `rc/dein.toml` | dein で管理するプラグイン一覧 |
| `.bashrc` | 末尾に fzf の初期化と `changed` / `review` / `cw` 関数 |
| `~/.gitconfig` | delta を git の pager にする設定（dotfiles 管理外） |

同じディレクトリの `vim-review-tutorial.md` は、練習用のリポジトリでこの文書の操作を一通り試すチュートリアル。
この構成を整えたときの変更内容は末尾の付録にまとめてある。

---

## 0. 最短の流れ

**未コミットの変更**

```
cw ~/project/iso/<repo>     # tmux に左シェル / 右 claude のウィンドウを作り、右で実装させる
changed                     # 未コミットの変更があるリポジトリを一覧する
review                      # 1 つ選ぶと vim がステータス画面で開く
```

ステータス画面で次を繰り返す。

- `]c` で次のハンクへ（差分がその場に展開される）
- 採用するハンクは `-`（ステージ）、捨てるハンクは `X`
- 直したいファイルは `o` で開いて編集し、`:w` して `:q` で戻る
- 新規ファイル（Untracked 欄）は `o` で開いて読み、`:q` で戻って `-`
- Unstaged と Untracked が無くなったら `cc` でコミット

**コミット済みの変更**

```
review main...              # 今のリポジトリで、main から分岐した後のコミットを全部見る
review HEAD~3..             # 直近 3 コミット
review abc123^!             # コミット 1 つだけ
```

vim の中からは `:Review main...` でも同じ（`,gr` で `:Review ` まで入る）。

- タブ 1 が一覧。範囲内のコミットと、変更ファイル（`M` `A` `D` `R` と増減行数）が並ぶ
- ファイルの行で `Enter` を押すと、そのファイルの左右差分のタブへ移る
- 差分タブでは `]c` `[c` で差分間を移動、`gt` で次のファイル、`1gt` で一覧に戻る
- コミットの行で `Enter` を押すと、そのコミット（メッセージと全差分）が開く。`gq` で閉じる
- 終わったら `<Space>q` で全部閉じるか、`:qa` で vim ごと終わる

用語や仕組みがわからなければ 1 章、未コミットの変更の詳細は 2 章、
コミット済みの変更の詳細は 3 章、そのほかの画面とキーは 4 章、Claude Code との運用は 5 章にある。

---

## 1. 前提知識と段階的な覚え方

vim のプラグインや git の用語に慣れていない人向けに、2 章以降を読むのに必要な知識と、
覚える順番を書く。知っていれば飛ばしてよい。

### 1-1. vim 側の用語

**プラグイン**

vim 本体に無い機能を足すための、vimscript ファイルのまとまり。GitHub のリポジトリ 1 つが 1 プラグイン。
この環境では `~/.cache/dein/repos/github.com/<作者>/<名前>/` に clone されていて、
その中の `plugin/`（起動時に読まれる）、`autoload/`（必要になったとき読まれる）、`doc/`（ヘルプ）などを
vim が `runtimepath` という設定を通して読む。

例えば fugitive は `:Git` というコマンドとステータス画面の中のキー（`-` `cc` など）を足す。
どのプラグインが何を足しているかは 1-3 と、`rc/dein.toml` のコメントに書いてある。

**dein**

プラグインを入れたり更新したりする役のプラグイン（プラグインマネージャ）。`rc/dein.toml` に

```
[[plugins]]
repo = 'tpope/vim-fugitive'
```

と書くと、`.vimrc` の dein の節がこれを読み、`dein#check_install()` が未インストールのものを見つけて
`dein#install()` で clone し、`runtimepath` に加える。つまり

- 足す: toml に 3 行書いて vim を起動し直す
- 外す: toml から消し、vim で `:call dein#recache_runtimepath()` を実行してから起動し直す。
  dein はプラグインのファイルを 1 つのディレクトリ（`~/.cache/dein/.cache/.vimrc/.dein`）にまとめて読んでいて、
  toml から消しただけではそこに残り、読み込まれ続ける。clone したディレクトリも残るので、
  `:echo dein#check_clean()` で出てくるパスを不要なら手で消す
- 更新: `:call dein#update()`

**キーの読み方と Leader**

`.vimrc` の `nnoremap <silent> <Space>s :Git<CR>` は「ノーマルモードで `Space` `s` と順に押したら
`:Git` を実行する」という意味。同時押しではなく順押し。よく使うキーはこの `<Space>` 始まりの 2 ストロークにしてある。

`,gr` `,gb` `,gl` `,gC` のように `,` で始まるキーは `<Leader>` を使ったもの（`nnoremap <Leader>gr ...`）で、
Leader はこの環境では `,`。`<Space>` のキーにも `,` 始まりの同じキー（`<Space>s` なら `,gs`）が残っているが、この文書では `<Space>` の方で書く。

`s` は `nnoremap s <Nop>` で単体の意味を消し、`sj` `sv` `sq` のようなウィンドウ・バッファ操作の頭文字にしてある。
押したキーが何に割り当てられているかは `:nmap <Space>s` や `:verbose nmap ,gr` で確認できる
（`verbose` を付けると、どのファイルの何行目で定義されたかも出る）。

2 文字以上のキーは、1 文字目を押してから `timeoutlen`（この環境では 1 秒）以内に次を押す。
間が空くと 1 文字目だけで確定してしまう。

**バッファ・ウィンドウ・タブ**

バッファは読み込んだファイルの中身、ウィンドウはそれを映す枠、タブはウィンドウの並べ方のひとまとまり。

「差分タブ」は vim の用語ではなく、この文書での呼び方。左右 2 つのウィンドウを diff モードで並べたタブのことで、
`:Review {範囲}` が変更ファイルごとに 1 つずつ作る。`<Space>d` やステータス画面の `dv` も同じ左右差分になるが、
今のタブの中でウィンドウを左右に分けるだけで、タブは増えない。

| 対象 | 作る | 移動 | 閉じる |
|---|---|---|---|
| タブ | `st`（空のタブ）、`:tabedit <ファイル>`、fzf の画面で `Ctrl-T`、`Ctrl-W T`（今のウィンドウをタブに移す） | `gt` `gT`、`{番号}gt` | `:tabclose` |
| ウィンドウ | `ss`（上下に分割）、`sv`（左右に分割） | `sj` `sk` `sh` `sl` | `:q` |
| バッファ | `:edit <ファイル>`、`<Space>f` | `sn` `sp`、一覧は `sb` | `sq`（`:bd`） |

レビューで開いたタブとウィンドウをまとめて片付けるのが `<Space>q`、vim ごと終わるのが `:qa`。

**diff モード**

2 つのウィンドウの内容を突き合わせて違いに色を付ける vim の機能。スクロールが連動し、
`]c` `[c` で違いの間を移動し、`do` `dp` で片方の内容をもう片方に写す。
行を揃えるために `------` の詰め物の行が出る。詳細は `:help diff-mode`。

**fugitive:// バッファ**

ステータス画面や差分タブの左側（比較元）、コミットの画面は、ファイルではなく
fugitive が git の情報から作った仮想バッファで、名前が `fugitive://` で始まる。
この環境では一覧（`sb` `:ls`）に出ないよう設定してある。

**quickfix とプレビューウィンドウ**

`:Rg` で複数選んだ結果や `:grep` の結果は quickfix（場所の一覧）に入り、`]q` `[q` で順に回れる。
`:copen` で一覧を開ける。プレビューウィンドウは補助情報を出す専用の小窓で、`:pclose` で閉じる。

**ヘルプ**

`:help fugitive` `:help fzf-vim` `:help dein` で各プラグインの説明が読める。
fugitive の画面では `g?` でその画面のキー一覧が出る。

### 1-2. git 側の用語

- **作業ツリー**: 手元のファイルそのもの。Claude Code はここを書き換える。
- **index**（ステージ、staging area とも言う）: 次のコミットに入れる内容の置き場。
  `git add` やステータス画面の `-` はここに書く。
- **HEAD**: 今のブランチの最新のコミット。
- **ハンク**: 差分のひとかたまり。連続した変更行と前後の文脈行で 1 つ。

未コミットの変更は、比較の組み合わせが 3 つある。

| 比較 | git のコマンド | ステータス画面での見え方 |
|---|---|---|
| index と作業ツリー（まだステージしていない変更） | `git diff` | Unstaged 欄 |
| HEAD と index（ステージ済みの変更） | `git diff --cached` | Staged 欄 |
| HEAD と作業ツリー（両方まとめて） | `git diff HEAD` | — |

2-1 の「ステージ済み = レビュー済み」という考え方はこの区別に乗っている。

コミット済みの変更は「範囲」で指定する。書き方は `git diff` と同じで、`:Review` と `review` もこれをそのまま受け取る。

| 書き方 | 意味 |
|---|---|
| `A..B` | コミット A から B までの差分 |
| `A..` | A から HEAD まで（`A..HEAD` と同じ） |
| `main...` | main と今のブランチの分岐点から HEAD まで。今のブランチで積んだコミットの分だけになり、main 側の変更は入らない |
| `abc123^!` | コミット abc123 の 1 つだけ |
| `HEAD~3` | HEAD の 3 つ前から**作業ツリー**まで。未コミットの変更も入る |
| `A B` | コミット A と B の差分（`A..B` と同じ） |

`HEAD~3` は「HEAD から 3 つさかのぼったコミット」。`HEAD~1` は 1 つ前。

### 1-3. 使うプラグインと画面

レビューで使うのは vim のプラグイン 2 つと、ターミナル側の delta。
ここではそれぞれが何をするもので、開くと何が出るかだけを書く。キーの一覧は 2 章以降にある。

**vim-fugitive: git の操作とステータス画面**

vim の中から git を使うためのプラグイン。`:Git` の後ろに git のサブコマンドを書くとそのまま実行できる
（`:Git log` `:Git blame` など）。引数なしの `:Git`（`<Space>s`）はステータス画面を開く。
`:Git status` のように引数を付けると、ただ `git status` を実行して結果を下のメッセージ欄に出すだけになり、
ステータス画面は開かない。

ステータス画面は `git status` の結果を vim のバッファにしたもので、ファイルが欄ごとに並ぶ。

```
Head: main
Help: g?

Untracked (1)
? test.sh

Unstaged (1)
M todo.sh

Staged (1)
M README.md
```

| 欄 | 並ぶもの |
|---|---|
| Untracked | git がまだ追跡していない新規ファイル（行頭 `?`） |
| Unstaged | 作業ツリーで変わっていて、まだ index に入れていないファイル（`M` は変更、`D` は削除） |
| Staged | index に入れたファイル（`A` は新規追加） |
| Unpushed / Unpulled | まだ push / pull していないコミット |

該当するものがない欄は表示されない。未コミットの変更のレビューは、ファイルやハンクを
Untracked と Unstaged から Staged へ移していく作業になる。

左右差分（`<Space>d` とステータス画面の `dv`）、blame 画面（`,gb`）、ログ画面（`,gl`）、コミットの画面も fugitive が作る。
`:Review` も中で fugitive の `:Git difftool -y` を使っている。

**fzf.vim: 絞り込み検索**

fzf はターミナルで動く絞り込みツールで、候補の一覧に対して文字を打つと、あいまい一致で候補が減っていく。
fzf.vim は、ファイル名・バッファ・`rg` の検索結果・コミットなどを fzf の候補にして vim から使うためのコマンド群
（`:Files` `:Rg` `:GFiles?` `:Commits` など）。レビュー専用ではなく、普段のファイル移動や検索にも使う。

この環境では、fzf の画面は vim の下 40% に出る。いちばん上が入力欄、その下に候補が並び、
右半分にカーソルのある候補のプレビュー（ファイルの中身や差分）が出る。`Ctrl-J` `Ctrl-K` で候補を上下に動き、
`Enter` で開く。何も開かずに閉じるのは `Ctrl-C` か `Esc`。

**delta: ターミナルの差分表示**

vim のプラグインではなく、`git diff` `git show` `git log -p` の出力を整形するターミナル側のツール。
git の pager に設定してあるので、これらのコマンドを打つと自動で使われる。
左右並び・行番号付き・シンタックス色付きで表示され、`n` `N` でファイル間を移動できる。

### 1-4. 段階的に覚える

一度に全部覚える必要はない。次の順で、各段階が手に馴染んでから次へ進む。

**Step 1. ステータス画面で仕分ける**

覚えるキー: `<Space>s` `]c` `-` `X` `cc` `gq` `g?`

`<Space>s` でステータス画面を出し、`]c` でハンクを順に見て、採用は `-`、却下は `X`、最後に `cc` でコミット。
これだけで、小さな変更のレビューは成立する。

**Step 2. 手直しして採用する**

覚えるキー: `o` `:w` `:q` `dv`

ステータス画面で `o` を押すとファイルが上に開くので、直して `:w`、`:q` でステータス画面に戻って `-`。
左右に並べて読みたいときは `dv`。

**Step 3. コミット済みの変更を一覧で読む**

覚えるコマンド: `:Review {範囲}`（`,gr`）、`review {範囲}`、一覧での `Enter`、`gt` `gT` `1gt` `]c` `[c` `<Space>q`

Claude Code がコミットまで済ませた変更や、日常のコミットを読む。3 章で扱う。

**Step 4. 調べる**

覚えるキー: `,gl` `,gb` `,gC` `<Space>e` `<Space>r` `<Space>R` `<Space>f` `sb`

「なぜこの行がこうなっているか」「同じ書き方が他にあるか」を vim の中で調べられる。
`,gb` で行ごとに最後に変更したコミットが並び、`<Space>r` でリポジトリ全体を文字列検索できる。

**Step 5. 複数リポジトリ**

覚えるコマンド: `changed` `review` `cw`

ターミナル側のヘルパーで、変更のあるリポジトリを一覧し、選んで vim を開き、
tmux に Claude Code 用の作業ウィンドウを作る。5 章で扱う。

練習用のリポジトリで Step 1 から 3 を通すのが `vim-review-tutorial.md`。

## 2. 未コミットの変更をレビューする

### 2-1. 考え方

Claude Code が書いた変更は、コミットする前に次の 3 つに仕分ける。

1. そのまま採用する → ステージする（`-`）
2. 手直しして採用する → vim で直してからステージする
3. 採用しない → 取り消す（`X`）

ステージ済みかどうかが「レビュー済みかどうか」の印になる。
Unstaged と Untracked の欄が無くなったら、そのリポジトリのレビューは終わり。

### 2-2. ステータス画面のキー

ステータス画面は `<Space>s`（`:Git`）か `:Review`（引数なし）で開く。シェルの `review` も最後にこれを開く。
`<Space>s` は今の画面を残したまま上に分割して開き、`review` や空の vim での `:Review` は画面いっぱいに開く。

| キー | 動作 |
|---|---|
| `]c` `[c` | 次 / 前のハンクへ。閉じている差分は自動で展開する。Untracked 欄のファイルの行にも止まる |
| `)` `(` | 次 / 前のファイルかハンクへ |
| `=` | カーソル行のファイルの差分をその場で展開 / 折りたたみ |
| `-` | カーソルのあるファイルかハンクをステージ / アンステージする |
| `X` | カーソルのあるファイルかハンクの変更を捨てる |
| `o` | カーソル行のファイルを上に分割して開く。読み終えたら `:q` で戻る |
| `dv` | カーソル行のファイルを左右差分で開く（左が index、右が作業ツリー） |
| `Enter` | カーソル行のファイルをステータス画面のウィンドウに開く（ステータス画面が置き換わる） |
| `cc` | コミットメッセージを書いてコミット |
| `gq` | ステータス画面を閉じる |
| `g?` | この画面のキー一覧 |

`-` と `X` は、ファイル名の行で押すとファイル全体に、展開した差分のハンクの中で押すとそのハンクだけに効く。
差分の行をビジュアル選択してから `-` を押すと、選んだ行だけをステージできる。

`X` で捨てた変更は作業ツリーから消える。ただし `X` を押すと、元に戻すためのコマンドが下に出る
（例: `To restore, :Gsplit f.txt|Gread 515da32`）。後から見るときは `:messages`。

ステージ済みのハンクは Staged 欄のファイルの差分に移る。そこで `-` を押すとアンステージに戻る。

### 2-3. 手直しする

直したいファイルの行で `o` を押す。ステータス画面の上にそのファイル（作業ツリー）が開くので、
編集して `:w`、`:q` でステータス画面に戻る。ステータス画面は自動で更新されるので、
`]c` で直したハンクを確かめて `-` でステージする。

左右を見比べながら直したいときは `dv`。左が index、右が作業ツリーのファイルで、右で編集して `:w` する。
左で編集して `:w` すると、その内容がそのまま index に書き込まれる（= ステージ）。
`dv` はステータス画面のウィンドウを左右差分に置き換えるので、終わったら `<Space>q` で片付けてから `<Space>s` で開き直す。

### 2-4. 新規ファイル

新規ファイルは Untracked 欄に出る。差分が無い（全部が追加）ので、`o` で開いて全体を読み、
`:q` で戻って、採用するなら `-` でステージする。`X` で消すこともできる。

### 2-5. ターミナルで同じことをする

ステージ・アンステージ・取り消しは、ターミナルの git コマンドでもできる。

| やりたいこと | コマンド | ステータス画面では |
|---|---|---|
| ステージする | `git add <file>` | `-` |
| ハンクを選んでステージする | `git add -p <file>`（ハンクごとに `y` / `n` で答える） | ハンクの中で `-` |
| ステージを外す（作業ツリーの変更は残る） | `git restore --staged <file>`、または `git unstage <file>` | Staged 欄で `-` |
| ハンクを選んでステージを外す | `git restore --staged -p <file>` | Staged 欄のハンクの中で `-` |
| 未ステージの変更を捨てる | `git restore <file>` | Unstaged 欄で `X` |
| ハンクを選んで未ステージの変更を捨てる | `git restore -p <file>` | Unstaged 欄のハンクの中で `X` |
| ステージ済みも含めて HEAD の状態に戻す | `git restore --staged --worktree <file>` | — |

- `git unstage` は `~/.gitconfig` の alias で、中身は `reset HEAD --`。ファイルを指定しなければ全部外れる
- `git restore` は `--staged` の有無で意味が逆になる。`--staged` を付けると index を HEAD に戻し（アンステージ）、
  付けないと作業ツリーを index に戻す（変更を捨てる）
- `git restore <file>` と `--worktree` 付きで捨てた変更は、git の履歴に残らないので元に戻せない。
  ステータス画面の `X` は元に戻すコマンドを表示してくれるので、迷うときはそちらを使う
- ファイルを指定せずに `git restore` だけを打つと、パスを指定するよう求めるエラーになり、何も変わらない
- 新規ファイル（Untracked）は `git restore` の対象外。消すときは `rm <file>`

## 3. コミット済みの変更を見る

### 3-1. 開き方

| 場所 | 方法 |
|---|---|
| シェル | `review {範囲}`（今いるリポジトリ）、`review <repo> {範囲}`（リポジトリを指定） |
| vim | `:Review {範囲}`。`,gr` で `:Review ` までコマンドラインに入る |

範囲の書き方は 1-2 の表のとおり。よく使うのは次の 3 つ。

- Claude Code にブランチで実装からコミットまでさせた → `review main...`
- 直近の何コミットかを見る → `review HEAD~3..`
- 特定の 1 コミットを見る → `review abc123^!`。ハッシュは `,gl` や `,gC` で調べる。
  `,gC` で選んで `Ctrl-Y` を押すとハッシュがレジスタに入るので、`:Review ` まで打ってから `Ctrl-R "` で貼る

範囲が間違っていたり、差分が無かったりすると、vim の下にメッセージが出てタブは作られない。

### 3-2. 一覧のタブ

`:Review` で開く 1 つ目のタブが一覧になる。

```
Review: main...
Enter: ファイル行はそのタブへ / コミット行はコミットを開く   gt gT: タブ移動   <Space>q: 全部閉じる

Commits (2)
  11c97e7 c3 add c, rename d, delete b
  9bcc44b c2 modify a

Files (4)
  M  a.txt           +1 -1
  D  b.txt           +0 -1
  A  c.txt           +1 -0
  R  d.txt -> e.txt  +0 -0
```

- **Commits**: 範囲に入るコミット。新しいものが上。範囲が作業ツリーまで（`HEAD~3` など）のときは HEAD までのコミットが出て、
  1 行目に「(作業ツリーまで)」と付く
- **Files**: 変更のあったファイル。行頭の記号は `M` 変更、`A` 追加、`D` 削除、`R` 名前の変更。右端は追加行数と削除行数
  （バイナリファイルは `binary`）
- 開いた直後のカーソルは Files の 1 行目にある

| キー | 動作 |
|---|---|
| ファイルの行で `Enter` | そのファイルの差分タブへ移る |
| コミットの行で `Enter` | そのコミットを上に分割して開く。メッセージと、そのコミットの全ファイルの差分が出る。`gq` で閉じる |
| `gt` `gT` | 次 / 前のタブ（= 次 / 前のファイル）へ |

内容を変えずに名前だけ変えたファイル（`R` で `+0 -0`）は差分タブが作られない。
その行で `Enter` を押すと、その旨のメッセージが出る。

### 3-3. 差分タブ

1 ファイル 1 タブで、左が範囲の始点、右が終点のファイルになる。

| 範囲 | 左 | 右 |
|---|---|---|
| `A..B` `main...` `abc123^!` | A（`main...` なら分岐点）時点のファイル | B 時点のファイル。読み取り専用 |
| `HEAD~3` など作業ツリーまで | HEAD~3 時点のファイル | 作業ツリーのファイル。編集して `:w` できる |

追加されたファイルは左が空、削除されたファイルは右が空になる。

| キー | 動作 |
|---|---|
| `]c` `[c` | 次 / 前の差分へ |
| `gt` `gT` | 次 / 前のタブ（= 次 / 前のファイル）へ |
| `1gt` | 一覧のタブへ戻る（`review` で起動したときと、空の vim で `:Review` したとき） |
| `do` | 右で押すと、左の内容を取り込む（右が作業ツリーのときだけ意味がある） |
| `<Space>q` | 一覧と差分タブを全部閉じる |

すでに何かファイルを開いている vim で `:Review` すると、今のタブの後ろに一覧と差分タブが足される。
その場合の一覧は `1gt` ではなく、`gT` で戻るか `{番号}gt` で移る。

### 3-4. 読んでいて直したくなったら

コミット済みの範囲（`A..B` など）の差分タブは読み取り専用なので、直すときは作業ツリーのファイルを編集する。

- 範囲を作業ツリーまでにして開き直す（例: `:Review HEAD~3`）と、右側のファイルをそのまま編集できる
- 直した後は、ステータス画面（`<Space>s`）で `-` してから、次のどちらかでコミットする
  - 新しいコミットにする: `cc`
  - 元のコミットに混ぜる: ステータス画面の Unpushed 欄や `,gl` のログ画面で、混ぜたいコミットの行にカーソルを置いて `cf`。
    コマンドラインに `:Git commit --fixup=<ハッシュ>` が入るので、`Enter` で `fixup!` コミットを作る。
    溜めた `fixup!` は同じ場所で `rf` を押すと rebase でまとめて混ざる。
    直前のコミットに混ぜるだけなら、ステータス画面で `ce`（amend）

`rf` `ce` は履歴を書き換える。push 済みのコミットに使うと force push が必要になるので、push 前のコミットに限って使う。

### 3-5. ターミナルで手早く見る

vim を開くまでもないときは、ターミナルで見る。

| コマンド | 内容 |
|---|---|
| `git diff --stat main...` | 変更ファイルの一覧と増減行数 |
| `git diff main...` | 差分の中身。delta が左右に並べて出し、`n` `N` でファイル間を移動する |
| `git log --oneline main..` | 範囲のコミット一覧 |
| `git show abc123` | コミット 1 つのメッセージと差分 |
| `tig main..` | コミット一覧の画面。コミットを選んで `Enter` で差分が開く |
| `git -c delta.side-by-side=false diff ...` | 画面が狭いときに上下並びで見る |
| `git pdiff ...` / `git pshow ...` | delta を使わず、通常の git の表示（上下並び、git 標準の色）を less で見る。`~/.gitconfig` の alias で、中身は `git -c core.pager=less diff` / `show` |
| `git --no-pager diff ...` | pager を使わず、そのままターミナルに流す |

### 4-1. Git まわりのキー一覧

### 4-2. fugitive の blame 画面（`,gb`）

右に作業ファイル、左に blame が出て、スクロールが連動する。

| キー | 動作 |
|---|---|
| `Enter` | blame を閉じ、その行を追加したコミットへ移動する。作業ファイルのウィンドウがコミットの画面に置き換わる |
| `o` / `O` | 同じものを横分割 / 新しいタブで開く。blame と作業ファイルは残る |
| `-` | カーソル行のコミット時点でもう一度 blame する（履歴をさかのぼる） |
| `A` `C` `D` | 列幅を author / commit / date まで縮める |
| `gq` | blame を閉じて作業ファイルに戻る |

`Enter` で開いたコミットの画面から作業ファイルに戻るには、`gq` か `Ctrl-O`。

### 4-3. fugitive のログ画面（`,gl`）とコミットの画面

ログ画面は `git log --oneline -50` の出力が横分割の一時バッファで開く。

| キー | 動作 |
|---|---|
| `Enter` | カーソル行のコミットを開く |
| `o` | 同じものを横分割で開く |
| `gq` | ログ画面を閉じる |

コミットの画面（ログ画面や `:Review` の一覧、blame から開いたもの）には、
コミットのヘッダ（`tree` `parent` `author` など）、メッセージ、全ファイルの差分が並ぶ。

| キー | 動作 |
|---|---|
| `]c` `[c` | 次 / 前のハンクへ |
| `diff --git` の行で `Enter` | そのファイルの、このコミットでの変更を左右差分で開く |
| `gq` | コミットの画面を閉じる（fugitive はこの画面に `gq` を割り当てていないので、`.vimrc` で `:bdelete` を割り当てている） |
| `coo` | そのコミットを checkout |
| `crc` | そのコミットを revert してコミット |
| `crn` | revert を index と作業ツリーに反映するだけでコミットしない |

|---|---|
| `<Space>f` | `:Files` |

## 5. Claude Code と組み合わせた運用

### 5-1. シェル関数

`.bashrc` 末尾に定義。探索先の既定値は `~/project/iso` 直下と `~/project/iso/worktrees` 直下。
環境変数 `REVIEW_ROOT` で変えられる。

| 関数 | 動作 |
|---|---|
| `changed [root]` | 未コミットの変更があるリポジトリを、変更ファイル数の多い順に表示 |
| `review [root]` | 未コミットの変更があるリポジトリを fzf で選び、そこへ `cd` して vim をステータス画面で開く。プレビューに `git status --short` と `git diff --stat HEAD` が出る |
| `review <repo>` | そのリポジトリへ `cd` してステータス画面で開く。未コミットの変更が無ければメッセージを出して何もしない |
| `review [repo] {範囲}` | そのリポジトリ（省略すると今いるリポジトリ）へ `cd` して、`:Review {範囲}` の状態で vim を開く |
| `cw [dir]` | tmux に新しいウィンドウを作り、左ペインをシェル、右ペインで `claude` を起動する。ウィンドウ名はディレクトリ名 |

`review` は、1 つ目の引数がディレクトリならリポジトリか root として扱い、ディレクトリでなければ範囲として扱う。
`.git` があるディレクトリがリポジトリ、無いディレクトリが root。

### 5-2. コミットさせずにレビューする流れ

1. `cw ~/project/iso/<repo>` で作業ウィンドウを作る。右ペインの Claude Code に実装させる。
   コミットはしないよう伝える。
2. 左ペインで `review .` を実行する。ステータス画面が開く。
3. 2 章の手順で仕分ける。`]c` で見て、`-` で採用、`X` で却下、直すなら `o` で開いて編集。
4. Unstaged と Untracked が無くなったら `cc` でコミットする。
   Claude にコミットさせる場合は、ステージ済みの内容だけをコミットするよう伝える。

### 5-3. コミットまでさせてからレビューする流れ

1. ブランチを切ってから Claude Code に実装させ、コミットまで任せる。
2. 左ペインで `review main...` を実行する。一覧のタブで、どのコミットでどのファイルが変わったかをつかむ。
3. ファイルの行で `Enter` を押して差分を読む。`1gt` で一覧に戻り、次のファイルへ。
   コミットの単位で読みたいときは、コミットの行で `Enter`。
4. 直す箇所があれば 3-4 の手順で直す。Claude に直させてもよい。直した後にもう一度 `review main...` で全体を確かめる。

### 5-4. 複数リポジトリの流れ

1. Claude Code に複数リポジトリへ変更を入れさせる。
2. ターミナルで `changed` を実行し、どのリポジトリに変更が入ったかを確認する。
3. `review` で 1 つ選ぶと、ステータス画面で vim が起動する。5-2 の手順 3 から 4 を行う。
4. `:qa` で vim を抜け、`review` を再度実行して次のリポジトリへ。
5. `changed` の出力が空になったら全リポジトリのレビューが終わり。
   コミット済みでも untracked ファイルが残っていると `changed` に出続けるので、
   不要な生成物は削除するか `.gitignore` に入れる。

### 5-5. 注意点

- `X` は作業ツリーの変更を捨てる。元に戻すコマンドが表示されるが、迷う場合は `=` で差分を見直してから判断する。
- `review` と `changed` は `.git` が存在するディレクトリだけを対象にする。
  worktree（`.git` がファイル）も対象に入る。
- fugitive のステータス画面では、fugitive 本来の `s`（ステージ）を外してある。`s` 始まりの
  ウィンドウ操作キー（`sj` `sv` `sb` など）と衝突するため。ステージは `-` で行う。
- fugitive:// の比較元バッファとステータス画面はバッファ一覧に出ない。`:bn` `:bp` `sb`（`:Buffers`）には
  作業ツリーのファイルだけが並ぶ。
- 差分タブの中でファイルを移るときは `gt` `gT` を使う。`sn` `sp` はバッファ移動なので、差分ウィンドウで
  押すと片側だけが別のファイルに置き換わって左右の対応が崩れる。崩れたら `<Space>q` で閉じて開き直す。
- bash で `!` を含む範囲（`abc123^!`）を打つとき、`!` が行末にあれば履歴展開されない。
  途中に入る場合はシングルクォートで囲む。

## 6. 設定を反映する手順

新しい環境や、設定を変えた後に行う。

```
# dotfiles の symlink を張り直す
sh ~/dotfiles/dotfilesLink.sh

# vim のプラグインを入れる
# .vimrc の起動時に dein#check_install が未インストール分を検出して入れるので、
# vim を一度起動して :messages でエラーが無いことを確認する
vim

# シェル設定を読み直す
source ~/dotfiles/.bashrc
```

`rc/dein.toml` からプラグインを外したとき（2026-10-15 の gitgutter と git-messenger もこれにあたる）は、続けて次を行う。

1. vim で `:call dein#recache_runtimepath()` を実行し、vim を起動し直す。
   これをしないと、外したプラグインがまとめ用のディレクトリに残って読み込まれ続ける。
   外れたことは `:echo exists(':GitGutter')` が `0` になることで確かめられる
2. `:echo dein#check_clean()` を実行すると、使われなくなった clone のディレクトリが出る。不要なら `rm -rf` で消す

brew で入れたものは `fzf` と `git-delta`。`rg` と `tig` は以前から入っている。

### 付録-3. 2026-10-15: プラグインを減らし、コミット済みの変更を見る機能を足した

最初の構成では `airblade/vim-gitgutter`（ハンクの記号表示と操作）と `rhysd/git-messenger.vim`（blame のポップアップ）も入れていた。
使ってみて次の理由で外した。

- gitgutter のハンク操作（ステージ・取り消し・プレビュー）は fugitive のステータス画面の `-` `X` `=` でできる。
  HEAD と比較する差分タブの中で使うと、ステージ済みの行にも `]h` が止まる、比較元にレビューと関係ない記号が出る、
  取り消しの後に `:w` が要る、といった注意点が多かった
- git-messenger は `:Git blame` と役割が重なっていた

あわせて次を変えた。

- `,gD`（index との差分タブ）と `,gH`（HEAD との差分タブ）を削除し、範囲を受け取る `:Review` に置き換えた。
  一覧のタブから `Enter` で各ファイルの差分タブに飛べる
- `review` は差分タブを作らずステータス画面を開くようにし、範囲を受け取れるようにした
- gitgutter のために入れていた `set signcolumn=yes` と `set updatetime=100` を削除した
- `,gq` を、カーソル位置に関係なく普通のファイルのウィンドウを 1 つ残すように変えた
- `sq` を `:q` から `:bd` に変え、`sQ` を削除した
- fugitive のコミットの画面に `gq`（`:bdelete`）を割り当てた
